OpenAI 兼容接口，按集群路由

推荐使用 POST /v1/chat/completions，可直接作为 OpenAI SDK 的 base_url=http://你的地址:9010/v1。兼容入口： /router/call-manage/chat/completions、 /api/v1/call-manage/chat/completions。请求体保持标准 OpenAI chat/completions 格式，model 建议留空，由服务端按 X-Async-Type 指定的集群选择模型。

接入地址

Base URL 与端点

推荐：POST /v1/chat/completions（OpenAI SDK 直接可用）

兼容：POST /router/call-manage/chat/completions

兼容：POST /api/v1/call-manage/chat/completions

支持 stream: true（SSE 原样透传）与普通 JSON 响应。模型名称、API 地址与 API Key 均在管理页配置，调用方无需接触上游地址。

模型列表：GET /v1/models（返回可用模型与集群）；内置聊天页：/chat。

鉴权

项目 Token / 上游 Key / 会员限额

推荐在「项目与密钥」创建项目，签发 sk-gw-... Token： Authorization: Bearer sk-gw-...。网关只把服务端配置的上游 Key 转发给厂商，项目 Token 不会外泄。

带 sk-gw- 前缀的 Token 一定会校验；无效、吊销、过期直接 401。 项目 Token 走项目级配额，不再叠加会员日限额。

不带 sk-gw- 前缀时保持旧语义：主链可覆盖上游 Key；携带 X-User-Id 的请求仍按会员等级校验每日次数。

项目配额与渠道健康

按项目隔离用量，失败自动换渠道

项目可设置每日/每月调用次数、Token 数和成本上限；留空=不限，0=禁止。 调用次数在请求前检查，Token/成本在响应后累计，属于软限额。

渠道按模型行统计今日成功率与 TTFB 延迟。连续失败达到阈值会熔断并冷却， 冷却后自动半开探测；同集群内会在连接失败、超时、429、5xx、401/403 时换渠道重试。 400/404/422 不重试。

集群路由策略可在「渠道健康」切换轮询、成本优先、延迟优先。成功响应会带 X-Request-Id、X-Gateway-Model、 X-Gateway-Cluster、X-Gateway-Retry-Count。

请求头

路由头、思考与 JSON 输出控制
请求头取值说明
X-Async-Type async1..async9 模型集群。主链建议 async1，异步链建议 async2；同集群内轮询
X-Purpose main / async1..async13 用途标识，仅用于日志与 token 用量记账，不影响模型选择
X-Thinking 1 / 0 思考模式开关；仅在模型「思考模式」为跟随请求时生效
X-Response-Format json_object 要求 JSON 输出（服务端按实际模型决定是否注入）
X-User-Id 用户 ID 调用方标识，用于用量统计与钻石计费；不传视为匿名
X-Generation-Id 生成 ID 同一次 AI 生成的所有调用共用；钻石计费按它聚合成本后结算
Authorization Bearer sk-gw-... 项目 Token；网关校验项目、配额与模型范围，不会转发给上游
X-Feature-Code 如 role_reply 功能码，用于用量分组统计；不传或非法记为 uncategorized
X-Request-Id 可选，≤64 字符 调用链路追踪 ID；不传由网关生成，并写入调用记录

集群与模型选择

集群在「大模型管理」中按模型配置
集群请求头典型用途
集群1async1主 LLM 默认池
集群2async2异步 / 后台任务默认池（原基础模型池）
集群3集群4 集群5集群6 集群7集群8 集群9
async3..async9 特殊分流或独立容量池

未传 X-Async-Type 时兼容回落：主链 async1、 异步链 async2。每个集群内所有启用模型按轮询调度。

模型配置了 temperature / top_p / top_k / max_tokens 时，服务端会覆盖请求体同名参数；留空则沿用客户端值。

temperature 与 top_p 互斥，只能配置一个；top_k 仅部分厂商支持。o 系列跳过采样参数，Claude 开启思考时固定 temperature=1。

cURL 示例

流式请求主链集群
bash
curl -X POST "https://your-domain/router/call-manage/chat/completions" \
  -H "Content-Type: application/json" \
  -H "X-Async-Type: async1" \
  -H "X-Thinking: 0" \
  -H "X-User-Id: demo-user" \
  -d '{
    "model": "",
    "messages": [
      {"role": "user", "content": "你好"}
    ],
    "stream": true
  }'

Python 示例

非流式请求异步集群
python
import requests

resp = requests.post(
    "https://your-domain/router/call-manage/chat/completions",
    headers={
        "Content-Type": "application/json",
        "X-Async-Type": "async2",
        "X-Purpose": "async13",
        "X-User-Id": "demo-user",
    },
    json={
        "model": "",
        "messages": [{"role": "user", "content": "你好"}],
        "stream": False,
    },
    timeout=120,
)
print(resp.json())

响应与错误

流式返回标准 SSE；非流式返回上游 JSON 信封
状态码含义处理建议
200成功流式读取 data: 事件，直到 [DONE]
400X-Async-Type 非法使用 async1..async9
502上游厂商返回错误检查提供商地址与 Key，或切换模型
503所选集群没有可用模型在「大模型管理」中启用该集群模型

temperature 0 ~ 2
越高内容越随机；与 top_p 互斥，填写一个会禁用另一个。
top_p 0 ~ 1
核采样，仅保留累计概率前 P 的 token；与 temperature 互斥。
top_k ≥ 1
仅保留概率最高的 K 个 token；部分厂商不支持。
max_tokens ≥ 1
单次响应的最大输出 token 数。
留空表示沿用客户端请求参数；temperature 与 top_p 只能填写一个。
仅 OpenRouter 提供商会启用该参数。
